# Bundle format (`.bpk`), version 2

The bundle is the only thing the Ballistic engine reads. `ballistic-pack`
builds it from a user's own Ballance installation. Original formats (NMO, BMP,
TGA, WAV) never reach the engine.

Goals: fast to load, GPU-ready, easy to debug with standard tools,
**reproducible** (the same install and packer version always give a
byte-identical bundle), and explicitly versioned.

## Container

A standard **zip** archive. Entries are deflate-compressed, except audio, which
is already compressed and is stored. Paths use `/` and are lowercase.

```
manifest.json
data/physics.json
scenes/<key>.bscn
textures/<key>.ktx2
sounds/<key>.ogg
```

Keys are lowercase paths relative to their source folder, without extension:
`Textures/sky/Sky_A_Back.bmp` becomes texture key `sky/sky_a_back`, and
`3D Entities/Level/Level_01.NMO` becomes scene key `level/level_01`.

## `manifest.json`

```json
{
  "format": "ballistic-bundle",
  "format_version": 9,
  "packer_version": "0.1.0",
  "source": { "variant": "gog", "verified_files": 312, "modified_files": 0, "unknown_files": 0 },
  "options": { "texture_encoding": "bc", "audio_encoding": "vorbis", "audio_quality": 0.6 },
  "scenes":   [ { "key": "level/level_01", "objects": 228, "meshes": 128, "materials": 41 } ],
  "textures": [ { "key": "floor_top_flat", "width": 128, "height": 128, "format": "bc1-srgb", "mip_levels": 8, "has_alpha": false } ],
  "sounds":   [ { "key": "misc_checkpoint", "sample_rate": 44100, "channels": 1, "frames": 52000, "format": "vorbis" } ]
}
```

The engine refuses any bundle whose `format` or `format_version` it doesn't
support, and tells the user to re-run the packer. The manifest has no timestamps.

## Scenes (`.bscn`)

```
8 bytes  magic   "BLSCENE\0"
u32 LE   scene format version (1)
…        postcard-encoded `Scene` (see `crates/ballistic-bundle/src/scene.rs`)
```

A scene is the geometry content of one source file (a level, a prefab, the
ball models, the menu background):

- **meshes**: interleaved vertex buffer (`position: [f32; 3]`,
  `normal: [f32; 3]`, `uv: [f32; 2]`, 32 bytes per vertex) and a `u16` index
  buffer. Both are stored as raw little-endian bytes that can be uploaded to the
  GPU as-is. Faces are sorted into **submeshes**, one per material.
- **materials**: the original's fixed-function material state as plain enums.
  Colours are `[f32; 4]` RGBA in the original's gamma space. Textures are
  referenced by key.
- **objects**: name, world transform, optional mesh, optional parent, kind
  (entity, light, camera), hidden flag.
- **groups**: name and member object indices. Group names carry the gameplay
  meaning (`Phys_Floors`, `PC_Checkpoints`, `Sector_01`, …). Resolving them into
  gameplay structures happens in a later version of the format.

Prefab scenes (`ph/…`) keep every mesh of their file, also those no object
uses: the moving elements' collision meshes are referenced only by their
scripts (by name, from `modules` in the physics data).

### Coordinate system

Bundles use **right-handed, Y-up** coordinates. The original engine is
left-handed, so the packer mirrors Z: positions and normals get `z → -z`,
transforms get `M' = S·M·S` with `S = diag(1, 1, -1)`, and each triangle's
winding is reversed to keep its facing. Units are unchanged (original world
units).

Transforms are 4×4, **column-major for column vectors** (load with
`glam::Mat4::from_cols_array_2d`).

## Textures (`.ktx2`)

Standard **KTX 2.0** files with a full mip chain, generated by the packer with a
box filter in linear light.

| Encoding | Used for | vkFormat |
|---|---|---|
| `bc1-srgb` | images that are fully opaque | `VK_FORMAT_BC1_RGB_SRGB_BLOCK` (132) |
| `bc3-srgb` | images with alpha | `VK_FORMAT_BC3_SRGB_BLOCK` (138) |
| `rgba8-srgb` | `--texture-encoding rgba8` (debugging / no BC support) | `VK_FORMAT_R8G8B8A8_SRGB` (43) |

Low-detail variants from the original (`sky_low/`) are not packed.

## Sounds (`.ogg`)

Ogg Vorbis at the source sample rate and channel count, quality-based VBR
(default 0.6). `--audio-encoding wav` stores 16-bit PCM WAV instead
(debugging). Low-quality variants (`Sounds_low/`) are not packed.

## Physics data (`data/physics.json`)

Physics parameters extracted from the original's scripts, as JSON (it's tiny
and useful to read). Since version 2.

- `gravity` is in bundle space (right-handed, Y up), units per second².
- `time_factor`: simulated seconds per real second.
- `balls`: one entry per ball type, named after its object in the `balls`
  scene. `force` is the per-step push impulse. `shape.kind` is `sphere` or
  `convex` (the radius is then the hull's bounding radius).
- `surfaces`: level groups that become static collision geometry.
- `props`: physics settings per prefab group (`P_Box`, `P_Dome`, …).
  `sphere_radius` is set for props simulated as spheres.
- `modules`: per moving element (`P_Modul_*`), and the level end's balloon
  (`PE_Balloon`), what its prefab script sets up. Names refer to objects and
  meshes of the prefab scene `ph/<group>`.
  - `bodies`: the Physicalize inputs. `convex` lists the meshes whose convex
    hulls make up the body, in the object's frame; empty means the object's
    own mesh. `shift_mass_center` is in the object's frame (bundle space).
  - `hinges`: `other: null` is the world. The pivot is the `frame` object's
    position, the axis its Z axis. `breakable`: the script destroys it (the
    balloon's bridge, at the finish).
  - `sliders`: `body` moves relative to `other` only along the line from the
    `axis_from` frame's position to the `axis_to` frame's; `limits` (if set)
    bound the displacement from the start.
  - `springs`: from a point on `body` (`anchor`: a position in a frame, or in
    world space without one) to a point on `other` (`other_anchor`), with
    rest `length`, `constant`, `linear_damping` and `global_damping`.
  - `ball_joints`: `body` and `other` share the `pivot` (a position in a
    frame), rotation free.
  - `forces`: the script's `Physics Force` nodes in script order: on `body`
    (`null`: the player's ball), at `position` (in a frame), along
    `direction` in `direction_frame`, with `value`. `graph` names the script
    graph it's in. When they act is the module's script logic.
  - `delays_ms`: the script's Delayer times, `proximities`: all its proximity
    tests, `boxes`: what it tests the ball's box against. Inputs to the
    module's script logic.
  - `wake`: the proximity test that wakes frozen bodies, and which bodies
    (`bodies`) it wakes.
  - `unsupported`: every other physics building block the script uses (none
    in Ballance now).
- `transformers`: the ball transformers (`Trafo Manager` in `Gameplay.nmo`).
  - `types`: each transformer prefab group (`ph/<group>`) and the ball it
    turns the ball into.
  - `reach`: the ball's centre must come nearer than this to the nearest
    transformer's origin.
  - `pull_*`: the pull into the transformer (*TT Set Dynamic Position*), in
    the transformer's frame, per axis. The ball settles at −`pull_offset`.
  - `pull_ms`, `hold_ms`, `swap_ms`: how long the pull runs, how long the
    ball then hangs before it bursts, and how long until the new ball
    appears (real time).
  - `animation`: the transformer's animation, with names from the
    `animtrafo` scene:
    - `root` is put at the transformer, and `bars` (with its children)
      stands in for it.
    - The ring parts move to `ring_offset` × the `ring_open` and `ring_close`
      progressions, each in its frame.
    - The bars move to `bars_offset` × `lift`, while the type's shadow
      material goes between the `shadow_colors`.
    - The `flash` field's texture scrolls by the `flash_scroll` offsets in
      turn, every `flash_ms`.
    - `ring_material` takes the transformer mesh's second material's
      colours.
  - A progression is a `duration_ms` and a 2D `curve`: control points with
    Hermite tangents, x from 0 to 1.
  - `pieces`: per ball type, the burst into pieces, with names from the
    `balls` scene. Each piece of `group` (children of `frame`) becomes a
    convex body. `mass` and `friction` are ranges, drawn per piece. Then each
    piece gets an impulse from the `impulse` range, along
    `impulse_direction` at `impulse_position`, in its own frame. `fade` and
    `fade_colors` fade the `materials` out.
    `sounds`: the pieces' `sound` (a bundle sound key). The `colliders`
    play it when they hit something faster than `min_speed`, at volume
    `min(speed / max_speed, 1)`, then stay quiet for `sleep_s` (simulated
    time), for `listen_ms` after the burst. With no colliders it plays once at
    the burst.
  - `pieces_fade_after_ms`: when a type's pieces fade out after a
    transformation from it.
  - `sound`: the sound the trigger plays, `delay_frames` later.

## Versioning rules

- Any change to entry layout or to a serialised type bumps `format_version`.
- Older bundles are never migrated; the player just re-runs the packer.
- History: **1** first release. **2** adds `data/physics.json`. **3** adds
  `modules` to it, and keeps every mesh in prefab scenes. **4** adds module
  `sliders`, `springs` and the wake-up targets. **5** adds `ball_joints`,
  `forces`, `delays_ms`, `proximities` and `boxes`. **6** adds the balloon
  (`PE_Balloon`), hinge `breakable`, force `graph`, and own-mesh bodies.
  **7** adds `transformers`. **8** adds the transformer `animation`, the
  ball `pieces` and `pieces_fade_after_ms`. **9** adds the transformer
  `sound` and the pieces' `sounds`.
